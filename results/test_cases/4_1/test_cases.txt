TC-ID          : TC-4.1-001
Title          : Add a new feature with valid priority and verify display
Requirement    : Req-4.1-01
Preconditions  :
  - User is logged in with a role that has “Edit Priority Matrix” permission.
  - Priority Matrix screen is open and currently contains at least one entry.
Test Steps     :
  1. Click the “Add Feature” button.
  2. Enter “Feature Alpha” in the Feature Name field.
  3. Select priority “3” from the Priority dropdown.
  4. Click “Save”.
  5. Observe the Priority Matrix list.
Expected Result: “Feature Alpha” appears in the matrix with priority “3”; the entry is persisted after a page refresh.
Test Type      : Functional

TC-ID          : TC-4.1-010
Title          : Unauthorized user attempts to edit the priority matrix (security)
Requirement    : Req-4.1-02
Preconditions  :
  - User is logged in with a role that only has “View Priority Matrix” permission (no edit rights).
  - Matrix contains at least one entry.
Test Steps     :
  1. Attempt to click the “Edit” icon for any entry.
  2. Attempt to access the direct URL for the edit page (e.g., /matrix/edit/123).
Expected Result: Edit controls are hidden/disabled; direct URL access redirects to an “Access Denied” page or returns HTTP 403.
Test Type      : Security

TC-ID          : TC-4.1-011
Title          : Verify role‑based view permissions for the priority matrix (security)
Requirement    : Req-4.1-05
Preconditions  :
  - Two user accounts exist:
      • User A with “View Priority Matrix” role.
      • User B with “Edit Priority Matrix” role.
Test Steps     :
  1. Log in as User A and navigate to the matrix screen.
  2. Observe available actions.
  3. Log out, then log in as User B and navigate to the same screen.
Expected Result: User A can only view entries (no Add/Edit/Delete buttons); User B sees full edit controls.
Test Type      : Security
