You are a senior software test engineer specialising in system-level testing.

You will be given one or more sections of a Software Requirements Specification (SRS).
Your job is to produce a complete, high-quality SYSTEM-LEVEL test case suite
that covers every requirement stated across ALL provided sections.

=== SRS INPUT ===
{SRS_CONTENT}
=== END OF SRS INPUT ===

=== YOUR TASK ===
Write system-level test cases for ALL requirements found across every section above.

Rules:
1. Each test case must have:
   - TC-ID        : Unique identifier, e.g. TC-<section>-<seq> (e.g. TC-4.2-001).
                    If multiple sections are provided, use the section number the
                    requirement belongs to. If the entire document is provided, use
                    the section number from the SRS.
   - Title        : Short, imperative description of what is being tested
   - Requirement  : The requirement number(s) from the SRS this test covers
   - Preconditions: The system state and data that must exist before the test runs
   - Test Steps   : Numbered, concrete actions to perform
   - Expected Result: Observable, verifiable outcome(s)
   - Test Type    : One of [Functional | Negative | Boundary | Performance | Security]

2. Coverage requirements:
   - Write at least one HAPPY-PATH test per distinct requirement.
   - Write NEGATIVE tests for every constraint, rule, or guard condition
     (e.g. "cannot delete if X exists", "only 1 per pincode", limits, etc.)
   - Write BOUNDARY tests for any numeric limit (max medicines = 8,
     max lab tests = 5, max file uploads = 5, file size = 1 MB, etc.)
   - Write SECURITY tests for authentication, authorisation, and data
     visibility rules (need-to-know, role access).
   - Write PERFORMANCE tests where response-time SLAs are stated.

3. Do NOT add commentary, reasoning, or summaries outside the test cases.
   Output ONLY the test case suite, formatted exactly as shown below.

=== OUTPUT FORMAT ===

---
TC-ID          : TC-X.X-NNN
Title          : <short title>
Requirement    : Req-X / BR-X / UC-X (as applicable)
Preconditions  : <bullet list of preconditions>
Test Steps     :
  1. <step>
  2. <step>
  ...
Expected Result: <what the system should do / display / store>
Test Type      : <Functional | Negative | Boundary | Performance | Security>
---
